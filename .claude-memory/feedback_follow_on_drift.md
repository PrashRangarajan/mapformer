Before proposing a batch, check it against the current plan's ranked list (docs/theory/*/00_PLAN.md) and the one novel
claim (per-head rank). Do not launch a batch whose question came from a post hoc secondary of the previous batch
without saying so and showing the cost. Keep secondaries labelled as secondaries in CLAUDE.md rows and the shared report.
Check that a registered stratum/floor actually requires the claimed ability (TW_STATECHANGE's T2drop was solvable by a
verb-agnostic "last noun at this cell" rule). A ceiling-bound CI is not precision.
**Why:** the 2026-10-04..10 week spent ~54 h of GPU on SCORE_RANK -> GAIN_GRAIN -> GAIN_PHASE -> TW_LANDMARK chains with
~1% effects; the independent review (`docs/audits/2026-10-11/CRITICAL_REVIEW.md`) found overclaims in results files,
CLAUDE.md and the report, and the user agreed to stop those lines.
**How to apply:** for each proposed GPU job state which plan item / claim it serves; prefer the cheapest test that could
kill the main claim. Related: [[feedback-batch-workflow]], [[feedback-gpu-sharing-and-cost]].
