MapFormer × PoPE — positional encodings on language

Position codes
on language

Two recent papers change how a transformer represents where a token is. MapFormer replaces the token’s index with a learned running sum, built for navigation; PoPE separates what a token is from where it is. This work tested both on language-like data — bracket languages, real code, text and music — and re-checked MapFormer’s navigation results at the length they were trained on. The clearest results: on bracket languages one layer of path integration is worth about three layers of ordinary attention; PoPE’s encoding improves MapFormer; and what makes MapFormer’s navigation solution hard to find is the rank of each attention head’s position map. On navigation, letting a step be negative is needed at the training length, not only beyond it.

The short version

  1. On Dyck-2, one layer of path integration is worth about three layers of ordinary attention. Trained and tested on the same bracket depth: +0.35 at one layer, +0.13 at two, +0.05 at three, +0.02 at four (8/8 seeds each). It buys parameter efficiency, not something depth cannot reach — given four layers and enough training, ordinary models get there too.
  2. PoPE’s encoding also improves MapFormer. At the training length the combined model beats MapFormer on every task where PoPE helps and is never detectably worse — so when a task needs path integration, add PoPE on top. Where position only counts tokens, plain PoPE (music) or plain RoPE (code) is better.
  3. MapFormer’s bottleneck limits it, and the deciding number is per attention head. On long navigation walks, every version giving each head a rank-2 position map finds the solution on 0 to 2 of 8 seeds; every rank-4 version on 8 of 8 — though rank 2 can represent and hold that solution. It is a problem of finding it. Rank 3 per head recovers most of the gap (6 of 8 seeds); twice the training does not rescue rank 2 (0 of 8).
  4. On navigation, the step has to be allowed to go negative. Trained and tested on the same 1024-step walks, forcing every step to be positive costs 0.177 accuracy: 0 of 8 seeds find the solution against 8 of 8. Earlier this cost had only been seen on walks longer than training.
  5. Path integration still works when the walk is told in words. With the moves buried in English prose (synonyms, fillers, asides), a one-layer path-integrated model scores 0.969 against 0.505 for a one-layer index model — exactly the score of always guessing the most common answer — and 0.772 for a two-layer one. It learns from prediction alone which words move it and that opposite directions cancel.
  6. The hard case is a rank equal to the world’s dimension, in 3-D as in 2-D. On a 3-D torus, rank 3 per head finds the solution on 1 of 8 seeds; rank 4 on 8 of 8 when the torus is large. Failures sit on revisits that are only reachable by wrapping around the torus.
  7. Trained path-integrated models keep what apart from where. Removing object identity from their attention scores leaves 0.97–0.99 accuracy; index models fall below the no-memory floor. This was checked after the fact, not pre-registered.
  8. A small leak of what into where, and a one-line fix. In MapFormer every token moves the position a little, objects included. Normalising the step’s input (NormStep) removes the leak and gains +0.011 on unseen objects (8/8, p = 0.0002), as much as an oracle told which tokens are moves. On navigation told in words it neither helps nor hurts. There, the oracle that only lets direction words move is beaten by learned steps: it confuses objects mentioned in passing with objects at the place.
  9. The model also tracks what changes in the world. When the story says “she dropped the cat”, a one-layer path-integrated model files the cat at that place (0.98 on the first return, against 0.65 for the best rule that ignores location) and keeps the sentence from moving its map. Index attention stays at the floor.
  10. On real stories it builds a clock of events, not a map. In a pilot on TinyStories its position ticks at sentences, speech turns and story ends; motion words barely move it, and it predicts no better than an index model.
  11. The leak and PoPE-style scoring are separate problems, and their fixes combine. The leak lives in the position itself, so changing how attention is scored leaves it untouched; NormStep removes it under either scoring rule. Together — moves set the position, the items being compared only set how strongly they attend — they give the most consistent model on unseen objects: 0.9994, 8 of 8 seeds, none below 0.998.
  12. Three published results replicate: MapFormer on Dyck-2, and PoPE on both Indirect Indexing and Bach Chorales.
  13. A 48-parameter fix matches a 786k-parameter one. A simple distance penalty in attention repairs long-context failures on Bach, and improved every model on real code (passing a t-test for two of the four, at three seeds).
  14. A simple data trick beats PoPE’s published Bach score by a wide margin — 0.394 against their 0.489.
  15. The metric the MapFormer paper uses on Dyck is unreliable. A model with no memory scores 0.88 on it, and it reports the effect running in the opposite direction to what it actually does.

Path integration on Dyck-2: worth about three layers

bracket language · trained and tested at the same nesting depth · width fixed · 8 seeds per cell, one batch of 210 runs

Dyck-2 is the language of balanced brackets, ( ) [ ]. To predict which closer is legal, a model must track a stack whose depth goes up on every opener and down on every closer — a signed quantity, which is exactly what a running sum represents and a token counter cannot. The natural objection is that a deeper standard transformer can learn to track the stack through attention alone. So width was held fixed and only the number of layers varied, with the models trained on the same bracket depth they were tested on:

  • 8/8 seedsDepth substitutes for it, roughly three layers to one. A one-layer path-integrated model matches a three-to-four-layer standard one. The advantage shrinks steadily with depth and vanishes at four layers once the standard models are trained long enough — so this is parameter efficiency, not a capability only path integration has.
  • CorrectedAn earlier version of this page reported +0.168 at four layers. That came from models trained on bracket depth 4 and tested at depth 12. Retrained at the depth they are tested on, the four-layer gap closes — it was extrapolation to unseen nesting depth, not a depth-proof advantage. The same batch also settled two side worries: the frequency setting of the standard models makes no difference, and their apparent plateau was partly just training budget.
  • 8/8 seedsVarying depth during training keeps the advantage. Training on a mixture of depths 4 to 12 leaves +0.110 at depth 12 with four layers. What removes the effect is training at one fixed depth with enough layers and budget — not depth-matching as such.

It agrees in direction with MapFormer’s own navigation result, measured at the training length: with a converged training recipe, path integration beats a matched index model by +0.243 (8/8; 0.971 against 0.805, floor 0.506). The two tasks share the property that makes a signed running sum useful — position that can move backwards.

The same exchange rate appeared on a second task: a walk on a 32-cell ring where the chance of stepping backwards is a dial. One path-integrated layer solves every setting (32 of 32 runs). Ordinary attention needs three layers wherever a step can be undone and one layer only when every step goes forward. Where a quarter or half the steps go backwards that is clear; where only one stretch in ten runs backwards it is a knife-edge — two layers fall short of the one-layer path model by 0.0115, against a threshold of 0.01, and most of those runs had stalled rather than converged. The pre-registered main readout, how one-layer attention accuracy moves along the dial, came out uneven (0.717, 0.676, 0.825, 1.000) and fit neither predicted pattern. Two of the eight seeds had been used in the pilot; the six fresh seeds alone give the same picture.

Three replications

published results reproduced from scratch

  • ReplicatesMapFormer on Dyck-2, on the paper’s own metric: MapFormer beats a two-layer RoPE by +0.370 (paper +0.44), 8/8. The ordering replicates (+0.064 on the more reliable closing-accuracy metric below); the paper’s absolute scores come in 0.015–0.112 lower here.
  • ReplicatesPoPE on Indirect Indexing — a pointer-arithmetic task — at 200k training steps, where it solves the task on 7 of 8 seeds. At their stated 100k it does not (1/8): training sits on a plateau and then drops suddenly at a point that varies from 65k to 157k steps between seeds, so the budget decides the outcome.
  • ReplicatesPoPE on Bach Chorales: PoPE beats RoPE by 0.032 NLL, 5/5, against their published 0.019.

Our PoPE implementation was also checked directly against the authors’ released code and matches to 1.7×10−6, so the comparisons above test PoPE as published.

Other positive findings

cheap fixes that outperformed elaborate ones

A 48-parameter fix for long contexts

Models trained on short sequences often break when run on longer ones. A distance penalty in attention — one learnable number per head, 48 in total — repairs this on Bach Chorales as well as a 786k-parameter alternative does:

MapPoPE4.6160.622
786k-parameter alternative, for comparison—0.616

Test NLL, lower is better, 5/5 seeds for each repair. On real code, rescored on the whole validation file, the same fix improved all four models on every seed, even at the training length. The gain passes a t-test for the two path-integrated models (MapPoPE p = 0.008, MapWM p = 0.036) and not for RoPE or PoPE — but these are three seeds each, and the models with and without the fix were trained in separate batches, so read it as likely rather than established. Plain RoPE plus the fix has the lowest score of the eight code models, but its lead is not established.

A simple data trick beats the published Bach score

  • 5/5 seedsTransposing the music by a few semitones during training — which PoPE’s paper applies to its other music dataset but not to Bach — improves PoPE by 0.107 NLL, over three times the 0.032 gap that separates PoPE from RoPE. Augmented PoPE reaches 0.394 against their published 0.489.

Path integration trains faster on pointer arithmetic

  • DirectionalOn Indirect Indexing the path-integrated model tends to reach the solution sooner — earlier on 6 of 7 paired seeds, median 70k steps against 100k — though the size of the speed-up is not statistically established. Given enough steps both reach the same end point, so this is about how fast it learns, not how well.
  • CaveatIt is also three times more robust to extra padding (0.430 vs 0.149 when examples are padded to a longer block, 6/7 seeds). Likely a robustness effect rather than a capability one, and not yet controlled.

  • DetectableAdding PoPE’s encoding to path integration is a good idea at the training length. Detectably better on two tasks (Bach, and Dyck at one and two layers), the same direction on code, and never detectably worse on any. Beyond the training context it can collapse — on Bach MapPoPE scores 4.616 against MapWM’s 1.397 — unless the 48-parameter fix above is added (0.622). If a task calls for MapFormer, use MapPoPE with the fix.
  • DirectionalAdding path integration to PoPE is not, on clock-like tasks. Where position only counts tokens, plain PoPE scores better on every seed (Bach 5/5, code 3/3), but neither gap is statistically established. The one such code contrast that passes a t-test is that path integration costs overall at the training length: +0.0056 bits per byte, p = 0.024 — at three seeds, where no distribution-free test can reach p < 0.05, so likely rather than established. A learned counter is slightly worse than the exact one the index provides for free.
  • 16/16 vs 10/16What MapPoPE gains comes from PoPE’s way of scoring, not from its extra frequencies. Our MapPoPE changed two things at once: how attention scores are formed (content sets only how much each frequency counts; position alone sets the phase) and how many frequencies each head has (PoPE’s 64 instead of MapFormer’s 32). A version with PoPE’s scoring but MapFormer’s 32 frequencies, tested on 16 fresh seeds of the paper’s navigation task, gets the whole gain: +0.024 over MapFormer (p = 0.012), solving 16 of 16 seeds against 10 of 16. Doubling the frequencies adds +0.0002, pinned between −0.0004 and +0.0008. PoPE’s scoring also lets the low-rank bottleneck work on these short walks. On long walks (1024 steps) it does not: a pre-registered test found both scoring rules solving 3 of 12 seeds at rank 2. PoPE’s scoring repairs revisits after short gaps (+0.115) but not the revisits that are only reachable by going around the torus, which are exactly where rank 2 fails. The two fixes address different defects: the scoring rule fixes the local map, the extra rank fixes the periodic code.
  • 20/20The simplest version of PoPE’s scoring is enough. MapFormer’s episodic-memory variant and MapPoPE sit at two ends of one family: content sets a gain on a position pattern, either one gain for everything or one per frequency. A version where content sets a single non-negative gain per token — the field always centred on the current place, only its strength changing — solved 20 of 20 seeds, as good as MapPoPE (also 20/20), and reached the solution about three times faster (on that task; on the harder new-object task below it was no faster). One caveat: on these seeds plain MapFormer also solved 18 of 20, so the task did not reveal much of a cost to avoid. Making the episodic-memory variant’s gain non-negative a different way, by squashing its content score, hurt (12/20 against 19/20): the form of the gain matters, not its sign.
  • In practiceThe two ideas are not symmetric partners. PoPE’s encoding reliably helps a path-integrated model where it helps at all, but on its own it is not a general improvement: it wins on music, is small on Dyck, ties RoPE on code (and is worse once both have the distance fix, p = 0.002 at three seeds), and loses on the navigation index model. Path integration is a specialist tool for where the angle comes from — worth it when position is genuinely signed, as in navigation and bracket structure, and not otherwise.

A navigation check: the step has to be able to go negative

torus navigation · trained and tested on 1024-step walks · 4 models × 8 seeds, one batch

MapFormer’s step can be negative, so moving east then west cancels. Several published designs force the step to be positive, which turns position into a clock that only moves forward. An earlier test found that costly only on walks longer than training, which is the kind of result this page treats as robustness, not capability. So it was re-run with every model trained and tested at the same length:

  • 8/8 vs 0/8The sign is a capability, not only robustness. Forcing the step positive costs 0.177 at the training length (p = 0.0002). In the trained signed models opposite moves cancel almost exactly (0.06 on a scale where 0 is perfect cancellation and 2 is none); in the positive-only models they cannot (1.92–1.97).
  • ReplicatesThis is known elsewhere. Sarrof et al., Grazzi et al. and Selective RoPE show that positive-only updates cannot track states that go back; this carries it to navigation at the training length.
  • CaveatThe positive-only models stalled rather than converged, so the claim is that they do not learn it within this training budget, not that they never could.

A navigation check: MapFormer’s own bottleneck

torus navigation · trained and tested on 1024-step walks · 6 models × 8 seeds · identical starting weights except the bottleneck · 3-D follow-ups, 64 runs

An earlier result here favoured rank 4, but only on walks longer than those trained on, which is exactly the kind of result the measurement lesson below distrusts.   • 8/8 vs 2/8What decides it is the rank per attention head. Two further versions separate the candidates: whether the heads share one set of dimensions makes no measurable difference, and neither does the output layer’s scale. Only the number of dimensions driving each individual head’s angle does (p = 0.007). The paper states a per-head input layer but not the output layer’s shape; read literally its rank 2 is a 2-of-8 row, but with a full output layer it would be an 8-of-8 row.
  • 6/8Rank 3 per head recovers most of the gap. It finds the solution on 6 of 8 seeds with accuracy 0.987, against 0.885 at rank 2 (p = 0.027; 0.054 after correcting for two comparisons, so at the edge of the pre-registered test). Rank 3 and rank 4 are not distinguishable at 8 seeds. The two failures stall in the same code as rank 2’s, one where opposite moves do not cancel.
  • 0/8 vs 7/8Twice the training does not rescue rank 2. Trained from scratch for 1800 epochs instead of 900, rank 2 still finds the solution on none of 8 seeds (accuracy 0.894 → 0.908) against 7 of 8 at rank 4 (p = 0.0014). Five of the eight rank-2 runs were still improving slowly, so “never” is not shown — only that doubling the budget solves none.
  • ExistenceRank 2 can represent and hold the solution — it just rarely finds it. Squeezing a trained rank-4 model to rank 2 keeps 0.995 accuracy; trained further from there, rank 2 keeps it on 7 of 8 seeds, like rank 4. So the problem is search, not capacity.
  • 1/8 vs 8/8In 3-D the hard rank moves up by one: it is the world’s dimension. On a 3-D torus, rank 3 per head (equal to the dimension) finds the solution on 1 of 8 seeds, like rank 2 in 2-D (1/8, against 8/8 at rank 3 in the same environment, p = 0.0014). Rank 4 finds it on 8 of 8 on an 18-per-side torus (accuracy 1.000) but on only 4 of 8 on a 10-per-side one. The difference is wrap-around: on the small torus 71% of revisits are reachable only by going around the edge, and every failing model fails on exactly those (0.73–0.80 against 0.96–0.97 on the rest). One extra dimension is enough once the torus is large.
  • CaveatA 100-cell world is memorised, not mapped. In the matching 2-D check, a 10-by-10 torus led the model to learn its one training map (0.986 on it) and score 0.273 on an unseen one — so that half of the wrap-around test measured memorisation. The 3-D pair is the clean evidence; grid size also changes the number of cells and how often cells are revisited.
  • ScopeOne task, one length, two heads, a fixed budget. Rank 2 was shown to hold the solution for our shared version; for the per-head versions that is inferred.

Navigation told in words

the torus walk written as English · trained and tested on 1024-word texts (about 132 moves) · unseen maps · 3 models × 8 seeds, one batch

The same torus walk, but told as prose: “walked slowly north then paused and saw a lamp . headed left and found nothing .” The vocabulary is 58 words, with three synonyms for each direction (north, up, northward), verbs that do not themselves move, fillers, and asides that mention an object without a place. Nothing marks which words are moves. The model must predict the object seen on returning to a place it has visited, on a map it has never seen. A path-integrated model’s step is a learned function of each word, so it has to discover from that prediction alone which words move it, and which way.

Real language says “she thought about the north”. Pilots of steps that read their context (not registered) found that a step reading only nearby words works when the cue is within about three words; a step that also reads the layer’s hidden state learned the right step for distant cues on 4 of 4 pilot runs. The registered batch was stopped: these step designs are already published, so it would add a measurement, not a mechanism.

  • PilotOn real stories, path integration builds a clock of events, not a map. 79–87% of every word’s step is shared, and the position ticks fastest at sentences, speech turns and story ends — it counts what happens, not where. Is what kept apart from where?

torus navigation, then navigation told in words · checks on trained models, then two registered batches (3 and 4 models × 8 seeds) · 1 layer

The idea behind MapFormer, borrowed from models of the hippocampus, is a cognitive map: the model should keep where it is (built from the moves) separate from what it sees there (the objects), so that a learned sense of place carries over to new rooms and new objects. Two questions: do trained models actually separate them, and does anything leak from one to the other?

But a little of what leaks into where

In MapFormer every token, objects included, moves the position by its learned step; nothing tells the model which tokens are moves. It learns to give objects tiny steps, but not zero: the step is read from the token’s raw embedding, so an object’s step depends on its embedding’s size and direction. To test this, objects were made new in every sequence — fixed random codes, with a separate set never seen in training — and two fixes were trained alongside MapWM:

MapWM could reach zero leak too, so this is easier optimisation, not a capability MapWM lacks.

Split by source afterwards, almost all of it comes from the aside sentences (0.126 of 0.133 rad); fillers and adverbs shift NormStep less than MapWM. An aside carries a small net offset that keeps its object away from the place’s position — the mechanism in the next point. NormStep simply uses a larger one. Its learned offset is not the source either: most seeds had already neutralised it.
  • Post hocBeing told which words move is not the best you can do. The oracle stops at 0.972 on every seed, below the learned models that converge (0.99–1.00). Every one of its errors (78 of 78 and 89 of 89 on the two seeds checked) names an object from an aside — “she thought about a cat” — mentioned earlier at the same place. With no step on any other word, the aside’s cat sits at that place’s position. A learned step map moves the aside elsewhere. In language, keeping what out of where does not mean only action words may move.
  • MethodSwitching off dropout at test time can understate a model. Runs that had not converged to the clean solution score up to 0.16 higher on the same walks with dropout on, as in training. The cause is the dropout’s rescaling, not its noise: the models learned to expect attention scaled by 1/(1−p), and multiplying attention by 1.11 at test time, with no randomness, recovers every such run (0.83 → 0.99) and leaves converged runs unchanged. All models here were scored the same way, so the comparisons hold; the earlier text-world headline is, if anything, understated. Every committed batch has since been re-scored this way, re-running each batch’s own evaluation: no pre-registered verdict changes. Only the text-world models move (navigation in words: 0.969 → 0.993, so path integration’s lead grows from +0.464 to +0.488); torus, rank, sign, Dyck, ring and leak results move by 0.01 or less. Rescaled, every learned-step model also beats the direction-words-only oracle detectably (+0.024, p = 0.0002).

What this says about measurement

findings that apply beyond these models

The Dyck metric in the MapFormer paper runs the effect backwards

The paper scores Dyck-2 with F1 valid continuation. On that scale a model with no memory at all scores 0.884, higher than most real models, because two-thirds of positions only need the previous token. And on the same trained models it reverses the shape of the effect:

metrictraining length4× lengthsays the effect
closing accuracy, chance 0.5+0.357+0.136falls 2.6×
F1 (the paper’s metric)+0.075+0.306rises 4.1×

F1 heavily penalises probability placed on illegal tokens, and ordinary models place more there as sequences grow — so F1’s gap widens for a reason unrelated to tracking the stack. The paper’s “helps out of distribution” pattern on Dyck is produced by the metric.

  • MethodTrain at the length — and depth — you test at. Every claim here that one design is better and held up was measured at the training length. Testing past the training length measures something different — how gracefully a model degrades on lengths it never saw. That is worth having, as the 48-parameter fix shows, but it is not the same as being a better model. Many published positional-encoding comparisons are measured the second way.
  • MethodAveraged metrics favour the more local model. Bits per byte, F1 and any average over all positions are dominated by easy tokens, so when they disagree with a metric conditioned on the hard case, the average picks the model better at local prediction.
  • MethodA task’s floor predicts, before any training, whether an experiment can work. On real Python a no-memory model already gets 0.858 of brackets right and 99.7% of brackets close within 8 levels, so a stack test on code could never discriminate — and it did not.
  • MethodPoPE’s advantage over RoPE is large only on its own dataset, and that dataset is limited by overfitting — the augmentation result above is 3× the effect it is used to demonstrate. Elsewhere it is small (Dyck, +0.01 to +0.03) or absent (code).
  • MethodThree seeds cannot settle small effects. The common “effect larger than 2.8·sd/√n” rule is a 10.7% false-positive test at three seeds, not 5%; small code differences quoted at n=3 are therefore not established.

What didn’t hold up

kept here so none of it gets re-cited

  • RetractedA large advantage on real code at long lengths disappeared once models were trained at the length they were tested at — the source of the “train at the length you test at” lesson above.
  • RefutedThree proposed explanations — that it works on code because code nests, that PoPE extrapolates because its magnitudes can’t go negative, and a clock-versus-map rule predicting when PoPE helps — each failed its own registered test. (Describing positions as signed or counting still stands; the prediction built on it did not.)
  • CorrectedTwo headline numbers were too big. Navigation’s +0.461 came from an under-trained recipe (+0.243 converged), and the Dyck advantage was first described as at the training length when it is at three times the training depth.
  • Withdrawn“Rank 2 loses because its code is skewed” and “the rank gap is just training speed” — replaced by the matched test above.
  • Retracted“Extra depth replaces path integration” came from a comparison that changed width along with depth; the fixed-width result above supersedes it.

A consistent pattern across the week: controlled interventions reproduced every time; proposed explanations of why did not. The results on this page are the interventions.
