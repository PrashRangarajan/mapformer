# Repository cleanup plan (2026-10-29)

Built from four read-only inventories in this folder: `INVENTORY_REPORTS.md` (1,102 top-level reports and outputs),
`INVENTORY_CODE.md` (968 code files), `INVENTORY_DOCS.md` (2,213 docs files plus `papers/`) and `INVENTORY_RUNS.md`
(`runs/` 30.7 GB, plus data outside the repo).

The plan has five principles:

1. **Never lose a cited number.** Every number cited in the drafts, CLAUDE.md or the claim map stays reproducible: its
   results file, its analysis output, the analysis script, and the files the script reads.
2. **Archive, don't delete, tracked history.** Use `git mv` into `archive/`. Deletion is for byte-identical duplicates,
   regenerable build products and untracked checkpoints, and checkpoints only after an approved tier.
3. **Don't move what code reads by path.** 363 scripts read or write top-level result files by fixed path, and about 70
   audit scripts and 3 registered analyses read `docs/` files. So cited and registered files stay where they are.
4. **Small, reversible commits,** one category per commit, verified before and after. `python3 -m mapformer.test_guards`
   and the selftests of the live analyses must pass after every code step.
5. **Pre-registrations are never edited.** Where a pre-registration cites a moved document, a redirect note covers it.

Already done (2026-10-28): the personal PDF is untracked (kept locally); 521 untracked small result files and the 64
Memory Maze `results.json` (cluster paths redacted, analysis reproduced exactly) are committed; 56 orphaned data-loader
processes were ended, freeing about 12 GB of RAM.
